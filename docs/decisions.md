# 앱 기능 결정 기록

앱 기능의 세부 결정. 인프라 · 아키텍처 결정은 [인프라 저장소 04 설계 결정](https://github.com/yubin05/hotel-booking-aws-v2/blob/main/docs/04-decisions.md)에 있다.

## APP-001 데모 결제는 "예약 먼저 + 10분 결제 대기", 결제 상태는 새 테이블 (2026-11-18)

- **상황:** 봇이 예약만 잔뜩 해 객실을 묶어 두는 문제의 대책으로 토스페이먼츠 테스트 키 결제를 넣는다. 이관 부하 시험(3단계)은 1단계와 같은 k6 시나리오로 예약 API를 부른다.
- **결정:**
  - 예약하면 객실을 잡아 두고 결제 대기. 10분 안에 결제 승인을 받으면 확정, 지나면 서버마다 1분 간격으로 도는 정리 작업이 예약을 취소한다(날짜 · 쿠폰 · 적립금 되돌림). 실제 예약 사이트의 "결제 중 재고 잡기"와 같은 방식.
  - 결제 상태는 새 `payments` 테이블에 둔다. 이관(덤프 복원) 때 이미 있는 `bookings` 테이블의 구조는 바뀌지 않기 때문.
  - 카드 번호는 토스 결제창에만 입력되고, 서버는 결제 키로 승인 API만 부른다. 금액 · 주인 · 마감을 서버가 다시 확인하고, 같은 승인을 다시 보내도 한 번만 처리.
  - 시크릿 키가 없으면 결제 없이 바로 확정한다. 키를 넣기 전의 배포 환경과 이관 부하 시험이 지금과 같은 동작으로 돈다. 쿠폰 · 적립금으로 0원이어도 바로 확정.
  - 결제 중이거나 결제한 예약은 금액이 바뀌는 날짜 변경을 받지 않는다(같은 박수로 옮기기 · 인원 변경은 됨). 결제 대기 예약은 숙박 완료(적립)로 바꿀 수 없다.
- **버린 대안:** 결제 먼저(승인 뒤 예약 생성) - k6가 결제창을 거칠 수 없어 1단계 기준선과 같은 시나리오로 비교할 수 없고, 결제하는 사이 방을 뺏기면 결제 취소까지 만들어야 한다. 결제 선택(바로 확정 + 나중에 결제) - 봇의 객실 묶기에 효과가 없다.
- **한계(코드에 shortcut 주석):** 취소해도 토스 환불 API는 부르지 않음(테스트 키라 돈이 오가지 않음). 승인 API를 부르는 동안 예약 행을 잠가 둠. 원 미만은 반올림.

## APP-002 예약 확정 알림은 응답 뒤에 보내고, .local 주소에는 보내지 않는다 (2026-11-18)

- **결정:** 확정 응답을 먼저 돌려주고 메일 · 카카오톡은 그 뒤에 보낸다. 실패해도 예약은 그대로이고 로그만 남긴다. 시드 · 테스트 · 부하 시험 계정(`.local`)에는 보내지 않는다. 보내는 주소(`MAIL_FROM`)가 없으면 메일 대신 제목만 로그에 남긴다.
- **이유:** 외부 API 시간이 예약 응답에 더해지면 이관 부하 시험의 p95가 바뀌고, 외부 장애가 예약 실패로 번진다. `.local` 주소로 보내면 SES 반송 · 샌드박스 오류만 쌓인다.
- **한계:** 큐 없이 서버 안에서 바로 보내 태스크가 그 순간 꺼지면 알림을 잃는다. 놓치면 안 되면 SQS 같은 큐로 옮긴다.

## APP-003 카카오톡은 기존 계정에 카카오를 연결해 "나에게 보내기"로 (2026-11-18)

- **결정:** 이메일로 로그인한 손님이 "카카오톡 알림 받기"를 누르면 카카오 동의(메시지 전송, `talk_message`) 후 연결하고, 예약 확정을 손님 본인의 "나와의 채팅방"으로 보낸다. 접근 토큰(약 12시간)이 만료되면 다시 연결한다.
- **이유:** 실제 숙박 서비스는 예약 안내에 알림톡(카카오 비즈니스 채널 · 템플릿 심사 · 발송 대행 · 유료)을 쓰지만, 사업자가 없는 개인 포트폴리오는 쓸 수 없다. "나에게 보내기"는 심사 없이 본인에게 보낼 수 있다([카카오톡 메시지](https://developers.kakao.com/docs/latest/ko/kakaotalk-message/common)).
- **버린 대안:** 카카오로 로그인(SSO)까지 - 비밀번호 없는 계정 · 이메일 미동의 처리가 더 필요해 크다. 후속 후보.
- **한계:** 갱신 토큰은 저장하지 않음(갱신 방법을 공식 문서로 확인하지 못함). 접근 토큰은 DB에 그대로 둠(RDS 저장 암호화). `state`는 이 사용자에게 서명한 10분짜리 값이라 남이 만든 연결 요청을 끼워 넣지 못한다.
